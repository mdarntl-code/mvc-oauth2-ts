# Практична робота: Авторизація OAuth 2.0 за патерном MVC

**Варіант 2:** Авторизація через Google або GitHub (OAuth 2.0).

---

## 🎯 Суть та розподіл ролей (MVC)

Уся програма складається лише з 4 простих файлів у папці `src/`:

1. **`models/UserModel.ts` (Model — Модель)**
   * **Що робить:** Описує інтерфейс `UserProfile` (`name`, `email`, `providerId`, `provider`) та зберігає користувачів у звичайний масив `users`.
   * **Важливо:** Модель нічого не знає ні про Google/GitHub, ні про консоль. Її завдання — лише тримати дані.

2. **`views/UserView.ts` (View — Представлення)**
   * **Що робить:** Виводить інтерфейс у термінал через `console.log`.
   * **Важливо:** Малює кнопки вибору ("1. Увійти через GitHub", "2. Увійти через Google") та картку профілю користувача. Вона не робить жодних обчислень.

3. **`controllers/AuthController.ts` (Controller — Контролер)**
   * **Що робить:** Зв'язує Модель і Представлення між собою:
     1. Отримує від сервера OAuth-токен.
     2. Отримує дані профілю з API.
     3. Передає отримані дані в Модель (`model.saveUser(...)`).
     4. Каже Представленню показати користувача (`view.showProfile(...)`).

4. **`index.ts`**
   * Створює об'єкти `Model`, `View`, `Controller` та запускає консольне меню.

---

## 💡 Шпаргалка для захисту викладачу

> **Питання: "Що таке патерн MVC і навіщо він потрібен?"**  
> **Відповідь:** MVC (Model-View-Controller) розділяє програму на три незалежні частини: дані (Model), інтерфейс (View) та логіку управління (Controller). Це робить код організованим і легким для тестування.

> **Питання: "Чому запит до API робить Controller, а не Model?"**  
> **Відповідь:** За принципом єдиної відповідальності, Model повинна відповідати лише за зберігання та стан внутрішніх даних. Логіка взаємодії із зовнішніми мережевими сервісами (API) та отримання OAuth-токенів належить до обов'язків Controller.

> **Питання: "Як дані потрапляють на екран?"**  
> **Відповідь:** Користувач тисне пункт меню -> Controller отримує дані через API -> передає їх у Model на збереження -> потім передає готові дані у метод `view.showProfile()`.
